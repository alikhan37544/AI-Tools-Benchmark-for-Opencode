Key insight: A model that fully fits in VRAM at a lower quantization (e.g., 14B Q4_K_M at 34 tok/s) will dramatically outperform a larger model that must offload to CPU (e.g., 27B Q4_K_M hybrid at ~10-15 tok/s). Fit-in-VRAM > parameter count for interactive use.

Blackwell MXFP4 Advantage

Your RTX 5060 Ti supports native FP4 tensor cores. MXFP4 quantization (4.66 bpW) is ~13.6% smaller than Q4_K_M.

Example: Gemma 4 26B-A4B at MXFP4-MOE = 13.70 GiB (fits), while Q4_K_M = 15.85 GiB (does NOT fit). Use MXFP4 when available.

Quick Setup Guide

Option A: Ollama (Recommended)

# Install Ollama
curl -fsSL https://ollama.ai/install.sh | sh

# Pull models
ollama pull qwen3-coder:32b
ollama pull qwen2.5-coder:14b

# Increase context window (default is often too small)
cat > Modelfile << 'EOF'
FROM qwen3-coder:32b
PARAMETER num_ctx 32768
EOF
ollama create qwen3-coder:32b-32k -f Modelfile

Option B: llama.cpp (Best Performance)

# Build with CUDA for RTX 5060 Ti
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=120a-real
cmake --build build --config Release -j$(nproc)

# Serve with full GPU offload
./build/bin/llama serve \
  -hf unsloth/Qwen3-Coder-32B-GGUF:Q4_K_M \
  --n-gpu-layers 99 \
  --ctx-size 32768 \
  --threads 12
